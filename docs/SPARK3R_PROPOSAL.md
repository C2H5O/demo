# Spark3R 修改提案：可靠上下文与窗口锚点感知的 KV 选择

状态：方案，未实现、未验证加速与新颖性。已阅读 [Spark3R 原论文](https://arxiv.org/html/2605.06270v1)；未找到可核查的官方代码链接，F 应标注论文算法复现，不冒充官方实现。

## 原方法与当前架构的差异

Spark3R 非对称处理 Q 和 KV：Q 按时空分组做合并，KV 沿时间采样。其基准规则对 S≤100 保留全部 Q、KV 基础步长为 1，但低敏感层可用三倍步长，因此短序列也可能减量。论文长序列的最高加速不能转移到这里。DA3-Small 的 12 层与论文实验的层配置不同，不能照抄敏感层列表。

本项目每次窗口为 32 帧，后续窗口包含全局/滚动锚点和重叠帧，槽位并不等同自然时间邻接。按槽位分组会混淆远距离锚点和近邻上下文。

## 提案

保留所有 Q 与稠密输出网格，只减少全局注意力 KV。高光像素仍需预测深度，因此保留它们的查询；高光 RGB 往往不能提供可靠纹理对应，可以降低其作为上下文 KV 的优先级。

1. 从当前 RGB 在 GPU 上计算低成本高光 mask 与纹理梯度可靠性。不增加 Teacher、光流网络或第二次前向，不用测试 GT 或深度真值选择 token。
2. 固定每层 KV 总预算，按真实帧 ID、空间网格和窗口锚点分配保底配额，保留所有 camera/register 等特殊 token。在剩余配额中优先保留非饱和且有纹理的上下文，给高光附近的非饱和组织保留一定支持；这是选择策略，不是已经实现的 ring loss。
3. 对重复帧使用绝对帧 ID 保持选择的一致性，降低跨窗口 token 集合跳变。可以复用选择索引，但不能直接缓存并复用上一窗口 K/V 特征，因为它们受窗口上下文影响。
4. 在训练划出的验证集校准敏感层预算。K 与 V 使用完全一致的索引，位置编码之后的 token 位置保持一致。注意力实际计算必须是 N×K，不能先构造 N×N 再遮挡，否则不会得到所需加速。DPT 接收原来的稠密 Q 输出。

## 最小验证路径

- E：稠密基准；F：Spark3R 参考；G：以上修改，完全相同 E 权重、32 帧窗口与融合。
- 扫描 KV 保留率 1/2、1/4、1/8；比较等总 KV 预算的 F/G、均匀采样与随机/空间配额控制。
- 分别去除可靠性选择、锚点配额、跨窗口索引一致性，证明每个额外机制的必要性。
- 报告 AbsRel、δ1、TAE、高光区域误差、窗口边界跳变、每层/总耗时、显存。总耗时必须包含选择、索引、融合和数据传输；额外报告预热后的纯网络耗时与端到端耗时，并以唯一输出帧计数，不能以重复窗口帧虚增 FPS。
- 建立验证集非劣容忍阈值，再冻结策略测 SCARED 8/9。速度目标暂为假设，先测 attention 的耗时比例 p；即使该部分加速 a 倍，总加速也只受 `1 / ((1-p)+p/a)` 约束。

## 论文定位

可尝试的机制主张是：内窥镜高光处应保留待恢复几何的查询，同时优先从可靠组织和跨窗口锚点获取上下文。仅“高光 mask 加 token pruning”可能不足以构成第三项创新。只有等预算下更好的几何/时间稳定性和实际端到端加速成立后，才能将其作为贡献；否则应降级为工程优化。需要继续检索可靠性感知 token selection 与视频窗口一致性剪枝的近邻工作。
